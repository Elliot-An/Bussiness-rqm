01 · PRODUCT CONTEXTPROBLEM & SCOPE
01 / Understand the problem

From watching lessons to retaining knowledge

The project report describes a platform for purchasing and learning from online video courses, with additional learning support through AI-generated questions and spaced repetition. The product goal is not only to deliver course content, but also to help learners check understanding and revisit knowledge.

Problem 01

Passive learning

Watching a lesson alone may not reveal whether a learner has understood the material or where their knowledge gaps remain.

Problem 02

Forgetting over time

Without a structured review process, learners may forget concepts after completing a lesson or course.

Product response

AI-supported practice

  • Generate practice questions from lesson content.
  • Provide feedback or explanations after answers.
  • Use learner performance to help focus practice on weaker concepts.

Spaced repetition

  • Track review outcomes for learning cards or concepts.
  • Update review state and interval based on performance.
  • Schedule future reviews to support longer-term retention.

BA observation
“Personalized” should be translated into observable behavior. For example, practice recommendations should use recorded learner performance and explain why a question or concept is prioritized, rather than relying on a vague promise of personalization.

02 · REQUIREMENTSUSER NEEDS & RULES
02 / Translate needs into requirements

Requirements for the practice experience

The following requirements are a portfolio-ready synthesis based on the report’s described capabilities. They are phrased as proposed, testable requirements to demonstrate BA thinking.

Functional requirements

IDRequirementPriority
FR-01The system should allow a learner to start a practice session associated with a lesson.Must
FR-02The system should present questions using supported types: single choice, multiple choice, fill in the blank, short answer, and true/false.Must
FR-03The system should record a learner’s submitted answer and the resulting evaluation.Must
FR-04The system should provide feedback or an explanation after an answer is evaluated, where available.Should
FR-05The system should use practice outcomes to help identify concepts that may need further review.Should
FR-06The system should maintain review state and schedule a future review according to the spaced-repetition rules.Must

Business rules to clarify

IDRule / decision pointWhy it matters
BR-01Only lessons accessible to the learner should be available for practice.Access control and consistent user experience.
BR-02The accepted answer format and evaluation method must be defined per question type.Prevents inconsistent grading, especially for short-answer responses.
BR-03Review scheduling should use a defined evaluation scale and state transition rules.Ensures predictable scheduling and easier testing.
BR-04If question generation fails or returns unusable content, the learner should receive a clear message and a recovery path.Avoids a broken practice session.
BR-05Generated questions should be associated with their source lesson and relevant learning content.Traceability and context for feedback.

Non-functional considerations

Reliability

Do not lose a submitted answer if a temporary error occurs; define retry and recovery behavior.

Usability

Use clear instructions, visible progress, understandable feedback, and accessible error messages.

Privacy

Limit learner-performance data to legitimate product purposes and authorized access.

Traceability

Link requirements to user stories, business rules, and test scenarios.

Process details and decision points

StepSystem / user behaviorDecision or validation
StartLearner selects a lesson and starts a practice session.Is the lesson available to this learner? Is practice content available?
Question deliverySystem retrieves or requests suitable questions for the lesson.Are questions valid, relevant, and in a supported format?
Answer submissionLearner answers and submits a question.Is the answer complete and in an acceptable format?
EvaluationSystem evaluates the response and presents feedback.Does the question type have a defined grading rule?
Progress updateSystem stores the result and updates learning progress.Can the outcome be saved? If not, can the learner retry safely?
Review schedulingSystem updates the review state and next review interval.Which state transition applies to this evaluation?

Example alternate flows

A1 · No questions available

Show a clear message, avoid opening an empty session, and offer a way to retry or return to the lesson.

A2 · Submission fails

Preserve the answer where feasible, explain that the result was not saved, and allow safe resubmission.

A3 · Unsupported answer

Validate input against the question type and tell the learner what needs to be corrected.

A4 · Review data missing

Use a defined initialization rule or surface an operational error; do not silently create an invalid schedule.

Key BA value
A workflow is useful when it exposes decisions, exceptions, and system responsibilities—not just the happy path. These decision points can become acceptance criteria and test cases.

04 / Define behavior that can be tested

Use cases and acceptance criteria

Use case UC-01

Complete a lesson practice question

Primary actor: Student

Preconditions: The student is authenticated, can access the lesson, and a practice question is available.

Main flow: The student opens practice, reads a question, submits an answer, and receives an evaluation with feedback where available. The system records the result.

Postcondition: The answer outcome is associated with the learner and relevant question or lesson.

User story 1 · Answer and receive feedback

As a learner, I want to answer practice questions after a lesson, so that I can check my understanding and identify mistakes.

Acceptance criteria · Gherkin-style examples

Given I can access a lesson and a valid practice question is available

When I submit an answer in the supported format

Then the system evaluates the answer and shows the result

And the system records the outcome against the relevant learner and question

Given I leave a required answer empty

When I try to submit the answer

Then the system follows the defined validation rule and explains what is required

User story 2 · Review at a suitable time

As a learner, I want the system to schedule reviews based on my previous results, so that I can revisit concepts I may forget.

Acceptance criteria · Gherkin-style examples

Given a learning item has a recorded review state and evaluation

When the review result is processed

Then the system updates the item’s state and next review interval according to the configured rules

And the next review time can be retrieved for display or notification

Clarification required before implementation
For short-answer questions, the team should agree whether answers are matched exactly, normalized (e.g., case and whitespace), checked against accepted alternatives, or evaluated through another method. The report identifies short answer as a question type, but this case study does not assume a specific grading policy.

Test scenarios and BA takeaways

These sample scenarios are proposed from the requirements above. They demonstrate how to turn requirements into observable outcomes; they are not evidence that the project passed these tests.

IDScenarioExpected result
TC-01Submit a valid single-choice answer.Answer is evaluated; result and feedback are displayed according to the rule.
TC-02Submit a multiple-choice answer with more than one selected option.System applies the agreed scoring rule and records the outcome.
TC-03Submit a fill-in-the-blank answer with leading/trailing spaces.System applies the documented normalization and comparison rules.
TC-04Submit a short answer that is semantically correct but worded differently.System follows the agreed short-answer evaluation policy; behavior is not left ambiguous.
TC-05Answer a true/false question.System evaluates the selected value using the configured correct answer.
TC-06Submit an answer while a temporary network or service error occurs.System communicates the failure and avoids falsely indicating that the result was saved.
TC-07Evaluate a new learning card.Card enters the configured initial learning state.
TC-08Evaluate a card in review with a low score.System applies the documented transition and interval adjustment.
TC-09Request the next due review after an outcome is saved.The returned due time reflects the saved state and configured scheduling rules.

Open questions worth resolving with stakeholders

  • How should the platform handle AI-generated questions that are duplicated, irrelevant, incomplete, or contain an incorrect answer?
  • Can learners report a question or flag an explanation as incorrect?
  • What exactly counts as a “weak concept,” and how much evidence is needed before prioritizing it?
  • What are the retry limits and recovery behavior when question generation or evaluation fails?
  • How should the product explain why a learning item is scheduled for review?

What this case study demonstrates

  • Breaking a product problem into user needs and functional requirements.
  • Mapping a core workflow and identifying alternate flows.
  • Writing user stories and acceptance criteria in testable language.
  • Connecting requirements to validation scenarios through traceability.
  • Identifying ambiguities and raising questions before implementation.
